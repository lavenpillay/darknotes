DarkNotes. Documentation

A canvas-based note-taking application with workspaces, groups, connections, and full MCP integration for AI-assisted note management.

Overview

DarkNotes is an offline-capable notes app that runs in your browser and is served by the local DarkNotes server. Notes live on a freeform canvas — you can position, resize, connect, and group them freely. While the server is running, your notes are saved to ~/.darknotes/data.json and become accessible to Claude and other AI tools through MCP.

📝 Rich note editing

Mixed text and checklist lines, heading fonts, colors, labels, and word wrap.

🗂️ Workspaces

Unlimited named workspaces, each with its own independent canvas and notes.

🔗 Visual connections

Draw bezier curve lines between notes to show relationships and ideas.

📦 Groups

Cluster related notes inside named, resizable, collapsible group containers.

🗺️ Minimap

Always-visible overview of the entire canvas with a draggable viewport window.

🤖 MCP server

Full CRUD access to your notes from Claude and any MCP-compatible AI client.

Two interfaces. DarkNotes is moving to a new web app (see below). The original app, served at http://localhost:3737, has every feature described in the guide sections from Interface to Import & Export. The new web app (http://localhost:3000 in development) already covers most of the canvas and adds the Style panel and safe syncing with Claude; the minimap and import/export are still to come. The MCP, REST and data-file sections apply to both.

Interface

The app has three main areas:

  • Toolbar — fixed top bar with workspace switcher, note count, MCP status indicator, zoom controls, and action buttons.
  • Canvas — the infinite scrollable/zoomable board where notes and groups live.
  • Minimap — collapsible overview panel in the bottom-right corner.

The small coloured dot next to the note count in the toolbar shows whether the DarkNotes server (API and MCP) is reachable: green = online, grey = offline.

Creating Notes

Click the + New Note button in the toolbar. New notes always appear at the centre of the current visible canvas area, accounting for your pan position and zoom level.

You can also duplicate any note by right-clicking it and choosing Duplicate. The copy appears offset 30px from the original.

Editing Content

Each note has a heading (top) and a line editor (body). The body is a line-based editor where every line is independent.

Line navigation

ActionKey

Line break within a lineShift+Enter
Delete empty line / move upBackspace on empty line
Toggle current line to checkboxTab

All lines support automatic word wrap — content wraps to the note width and the line expands vertically as you type.

Checklists

Checklists are inline with text — any line can be a plain text line or a checkbox line. You can freely mix them.

Creating checklist items

  • Click the ☑ Toggle Checklist button in the note's hover toolbar to convert the current line to a checkbox (or back to text).
  • Press Tab on any line to toggle between text and checkbox.
  • Press Enter on a checkbox line to create the next checkbox below.
Tip: A note can have any mix of text and checkbox lines in any order — for example, a paragraph, then a checklist, then more text, then another checklist.

Styling Notes

Colors

Hover a note to reveal its toolbar. Click the palette icon to open the color panel, which has 20 background colors and 10 font colors.

Font size

Use the font size dropdown (11–24px) in the note toolbar to adjust the body text size. The heading size is controlled separately in Settings.

Heading font & size

Click the sliders icon (Settings) in the note toolbar to open the heading settings panel. Choose from 19 Google Fonts across 5 categories (Serif, Sans, Mono, Display, Script) and adjust the heading size with a slider (12–36px). Each font is previewed in its own typeface.

Labels

Labels are hashtag-style tags attached to notes. Type a label name in the label input at the bottom of a note and press Enter to add it. Click the × on any label to remove it.

Labels are searchable and filterable via the MCP API.

Arranging Notes

Moving notes

Drag a note by its header bar or any empty area of its body. Notes snap to the top of the z-stack when clicked.

Resizing notes

  • Corner handle (bottom-right) — drag to resize width and height simultaneously.
  • Right edge strip — drag to resize width only.
  • Bottom edge strip — drag to resize height only.

Minimum note size is 220×140px.

Connections

Notes can be visually connected with bezier curve lines to show relationships.

1

Hover a note edge

Orange connection dots appear on the top, right, bottom, and left edges.

2

Drag from a dot

A live preview line appears as you drag across the canvas.

3

Drop on another dot

Release over any connection dot on another note to create the connection.

Connection lines follow notes as they are dragged or resized. Click any connection line to delete it.

Groups

Groups are named, semi-transparent rounded rectangles that sit behind notes, letting you cluster related notes visually.

Creating groups

Click the New Group button in the toolbar. The group appears on the canvas and can be named, repositioned, resized, and colored.

Adding notes to a group

Right-click any ungrouped note and choose Add to Group. A submenu lists all available groups by color and name. The note moves inside the group's bounds if it is currently outside.

Removing notes from a group

Right-click a grouped note and choose Remove from Group. The note stays at its current position on the canvas, now ungrouped.

Minimizing groups

Click the chevron ∨ button in a group's header bar to minimize it. The group collapses to a slim pill showing only its name, and all notes inside are hidden (along with their connection lines). Click the pill or the ∧ chevron to restore everything.

Group controls

  • Drag the header bar to move the group.
  • Resize handle (bottom-right corner) to resize.
  • Color dot — click to open the group color picker.
  • × button — delete the group (notes inside are ungrouped, not deleted).

Navigation & Zoom

Panning

  • Hold Space and drag to pan.
  • Middle-mouse drag to pan.
  • Scroll (without Ctrl) to pan.

Zooming

  • Ctrl+Scroll — zoom toward the cursor.
  • Ctrl+= / Ctrl++ — zoom in.
  • Ctrl+- — zoom out.
  • Ctrl+0 — reset zoom to 100%.
  • Toolbar − / + buttons and the ⊙ reset button.

Zoom range: 25%–300%. Zoom level is saved per workspace.

Minimap

The minimap (bottom-right corner) shows a live scaled-down view of the entire 4000×3000 canvas. Notes are rendered with their actual background colors. An orange rectangle shows the current viewport.

Minimap interactions

  • Drag the orange rectangle to pan the main canvas.
  • Click anywhere on the minimap to jump the view to that location.
  • ∨ / ∧ chevron in the minimap header to collapse it to a slim bar or expand it back.

Workspaces

Workspaces are completely independent canvases. Each has its own notes, groups, connections, pan position, and zoom level.

Workspace switcher

The workspace switcher pill in the toolbar shows the current workspace name. Click it to open the dropdown, which lists all workspaces with their note counts.

Creating workspaces

Type a name in the New workspace name… field at the bottom of the dropdown and press Enter or click +. A starter note is created automatically.

Renaming workspaces

Click the gear icon next to the workspace pill to open the Workspace Settings dialog. Edit the name and press Enter.

Deleting workspaces

Hover a workspace in the dropdown to reveal its × delete button. The last workspace cannot be deleted.

Import & Export

Export — Click the download icon in the toolbar. The current workspace is exported as a .json file named darknotes-{workspace-name}-{date}.json.

Import — Click the upload icon and select a previously exported JSON file. The notes are imported as a new workspace — your current board is not affected.

Clear All — Deletes all notes and connections in the current workspace only (after confirmation).

The New Web App

The new web app is a rebuild of the interface on Next.js and Tailwind, on top of the same server and data file. Start it together with the server:

npm install
npm run dev:all      # API server on :3737 and the new app on http://localhost:3000

Its board is the same canvas, so notes, groups, connections and workspaces made in one interface are there in the other, and Claude sees them through MCP.

What works today

  • Notes — create with + New Note, edit the heading and lines (Enter adds a line, Shift+Enter breaks a line, Tab toggles a checkbox, Backspace on an empty line removes it), add labels, drag anywhere that is not a text field, resize from the corner, right edge or bottom edge (minimum 220×140), and right-click for Duplicate, Add to / Remove from Group and Delete.
  • Connections — drag from a dot on a note's edge to a dot on another note (it snaps within 30 px). Click a line to delete it; right-click it to choose arrowheads (none, end, start or both).
  • Groups — + New Group. Drag the header to move the group and the notes inside it, resize from the corner, rename, recolour, minimize to a pill (hides its notes and their connections) or delete (the notes are kept).
  • Pan and zoom — scroll, Space + drag, middle-drag or drag empty board to pan; Ctrl/Cmd + scroll, Ctrl/Cmd + + / - / 0 or the toolbar buttons to zoom (25–300%). Pan and zoom are saved per workspace.
  • Workspaces — the list comes from the server, so workspaces created or renamed through MCP appear, and renames made here reach MCP. Hover a workspace in the dropdown to rename or delete it.
  • Style panel — colours, text size and heading font, with your own colours (below).

Not in the new app yet

The minimap, import and export of a workspace, and importing boards saved in the original app's browser storage. Use the original app at http://localhost:3737 for those.

Style Panel

Click Style in a note's footer to open one panel for everything about how that note looks. Changes apply to the note as you make them. Click outside the panel or press Esc to close it.

Colours

  • Note colour — 20 presets. Text colour — 10 presets. The selected colour has a ring.
  • A readout under the text colours shows the contrast between the text and the note (for example 9.6 : 1, easy to read) and warns when text will be hard to read: 7 : 1 or more is easy, 4.5 : 1 is readable, below that is low contrast. Translucent colours are blended with what is behind them first.

Adding your own colours

The + at the end of each colour row opens a picker with a saturation/brightness square, a hue slider, an opacity slider and a hex field (#rgb or #rrggbb). The note changes live while you choose. Click Save to palette to keep the colour as a swatch in that row, or Done to use it without saving.

  • Each row keeps up to 24 saved colours; when it is full the oldest makes room. Hover a saved swatch and click its × to remove it.
  • Saved colours belong to this browser (they are kept in its localStorage, not in the data file), so they do not appear in another browser. The notes themselves keep their colours everywhere.

Text size and heading font

  • Body text — a − / + stepper through 11, 12, 13, 14, 15, 16, 18, 20 and 24 px.
  • Heading font — a list of 20 fonts in groups (Default, Serif, Sans, Mono, Display, Script), each shown in its own typeface. Heading size is a slider from 12 to 36 px.
  • Reset to default restores the colours, sizes and heading font a new note starts with. Your saved colours are not touched.

The default font

New notes use a sans-serif heading font: MesloLG when it is installed on your computer, otherwise DM Sans. MesloLG is recognised under its common names (MesloLGS NF, the Nerd Font builds, plain Meslo LG and the for Powerline builds), and the font list says whether it was found. The default applies to notes created from the web app, through MCP and through the REST API alike. Notes you already have keep their fonts.

Saving & Syncing

You can keep the web app open while Claude edits your notes. The app saves only what you changed, and merges in what others changed, so neither side overwrites the other.

How it works

  • Edits show immediately. About half a second after you stop, the app sends just the differences (a move, a new note, a deleted group) to the server. The toolbar shows Saved, Unsaved changes, Saving… or Not saved.
  • The server's reply, and a check every 4 seconds while the tab is visible, bring in anything changed elsewhere. Notes, groups and connections Claude adds or edits appear on their own, and are never erased by one of your saves.
  • Things you create in the web app get random ids such as n_k3f9a2x, so they cannot collide with the n_1, n_2 ids the server hands out. Treat ids as opaque.

When both of you change the same thing

  • Different notes, or different fields of one note (you move it while Claude renames it): both changes are kept.
  • The same field of the same note before the next sync: your value wins until it is saved, then the last write wins. A note's lines are replaced as a whole, so two people typing in the same note at once can overwrite each other.
  • A delete beats an edit made on the other side.

Failures and offline

  • If a save fails, your edits stay on screen, the toolbar shows Not saved, and the app retries every 5 seconds. A save is also started when you hide or close the tab.
  • If the server cannot be reached when you open the app, it shows the copy it last cached in the browser, marked Offline, and sends your unsaved edits once the server is back.
Original app: the original interface on port 3737 still replaces the whole board each time it saves, so it can erase notes Claude added while its tab was open. Reload it before editing after Claude has changed things, or use the new web app.

MCP Integration — Overview

The DarkNotes MCP server exposes your notes to Claude and any Model Context Protocol-compatible AI client. You can ask Claude to read notes, create new ones, check off tasks, reorganise workspaces, and more — without opening the browser.

The server can be run directly with Node.js or as a Docker container. It offers two ways to connect:

  • MCP over stdio (the default mode) — Claude Desktop and Claude Code launch the server and talk to it directly.
  • HTTP server (API mode, port 3737) — serves the browser app, the REST API at /api, and the MCP Streamable HTTP endpoint at /mcp for remote or local MCP clients.
Note: All data is stored in ~/.darknotes/data.json. The app works fully offline without the server — localStorage is always kept in sync as a fallback.
Original app only: it keeps the list of workspaces and their names in the browser, so a workspace created or renamed through MCP or the REST API does not appear there, and notes Claude changes show up only after a reload. The new web app does not have these limits: it reads the workspace list from the server and merges Claude's changes in every few seconds (see Saving & Syncing).

Setup

1

Option A: Run with Docker (Recommended)

# Build the image
docker build -t darknotes .

# Run the container (persisting your notes).
# Publish the port on loopback only: the container binds all interfaces.
docker run -d \
  -p 127.0.0.1:3737:3737 \
  -v ~/.darknotes:/root/.darknotes \
  --name darknotes \
  darknotes

The container runs API mode. Open http://localhost:3737. If the port is reachable by anyone else, also pass -e DARKNOTES_TOKEN=… (see Configuration & Security).

2

Option B: Run with Node.js

npm install

npm run serve        # API mode: web app, /api and /mcp on http://localhost:3737
npm run mcp          # MCP over stdio only (what Claude Desktop / Claude Code launch)
npm run serve:mcp-http   # API mode plus a stdio MCP server in one process (does not start the new web app)
npm run dev:all      # API server (:3737) and the new web app (:3000) together, for development

Requires Node.js 22 or newer. npm run serve starts only the server (and the original app on port 3737); the new web app on port 3000 is a separate process, which npm run dev:all starts for you. Use npm run dev:server to restart the server automatically on file changes.

3

Connect an MCP Client over HTTP

Start API mode (Docker or npm run serve), then connect to the Streamable HTTP endpoint. Clients that send no browser Origin header (MCP clients, curl) work out of the box on localhost.

  • Endpoint: http://localhost:3737/mcp
  • Sessions: the first request is initialize; later requests carry the returned mcp-session-id header. DELETE /mcp with that header ends the session; idle sessions expire after 30 minutes.
  • Auth: none by default. If DARKNOTES_TOKEN is set, send Authorization: Bearer <token>.
claude mcp add --transport http darknotes http://localhost:3737/mcp
4

Configure Claude Desktop (Stdio)

Add to claude_desktop_config.json:

{
  "mcpServers": {
    "darknotes": {
      "command": "node",
      "args": ["--import", "tsx", "/absolute/path/to/darknotes/apps/server/src/index.ts"]
    }
  }
}

Config location — macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
Windows: %APPDATA%\Claude\claude_desktop_config.json

5

Configure Claude Code (Stdio)

claude mcp add darknotes -- node --import tsx /absolute/path/to/darknotes/apps/server/src/index.ts

Configuration & Security

The server is configured with environment variables.

VariableDefaultPurpose
DARKNOTES_PORT3737HTTP port.
DARKNOTES_HOST127.0.0.1Interface to bind. Loopback only by default; containers use 0.0.0.0.
DARKNOTES_TOKENnoneIf set, /api and /mcp require Authorization: Bearer <token>.
DARKNOTES_ALLOWED_HOSTSnoneExtra hostnames accepted in the Host header, comma-separated (* disables the check).
DARKNOTES_ALLOWED_ORIGINSnoneExtra browser origins accepted, comma-separated, e.g. https://notes.example.com.
DARKNOTES_DATA_DIR~/.darknotesDirectory that holds data.json.

What the server protects against

  • Network access — it listens on 127.0.0.1 by default, so only your own machine can reach it.
  • DNS rebinding — requests whose Host is not localhost, 127.0.0.1 or [::1] are rejected with 403.
  • Other websites — requests carrying a foreign browser Origin are rejected with 403, so a web page you visit cannot read or edit your notes.
Exposing the server: if you publish the port beyond your machine (a LAN, a reverse proxy, a container port mapped without 127.0.0.1), set DARKNOTES_TOKEN and add your hostname to DARKNOTES_ALLOWED_HOSTS. The browser app cannot send a token, so a token-protected server is for MCP and API clients.

Data & Privacy

All DarkNotes data is stored locally on your machine:

  • Browser: localStorage keeps a cached copy so the app can work offline (darknotes_* keys in the original app, darknotes:v3:* in the new one), and the new app's saved colours (darknotes:v1:palette).
  • MCP server: ~/.darknotes/data.json — plain, human-readable JSON. Back it up, version-control it, or copy it between machines freely.

No data is sent to any cloud service. The server listens on 127.0.0.1 by default and talks to Claude via stdio or HTTP on your own machine (see Configuration & Security before exposing it further).

How the data file is protected

  • Atomic writes — each save goes to a temporary file that is then renamed into place, so a crash cannot leave a half-written file.
  • Automatic backup — the previous version is kept as data.json.bak.
  • No silent reset — if data.json is not valid JSON, the server reports an error, leaves the file untouched and saves a copy as data.json.corrupt-<timestamp>. Fix or restore the file (the .bak is a good start) and retry.
  • Ids are never reused — id counters are repaired on load if they are missing or behind the existing notes.
Backup tip: Copy ~/.darknotes/data.json to back up all your workspaces, or export individual workspaces from the toolbar for sharing.
